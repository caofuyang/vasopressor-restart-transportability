# eICU核查后修正规则（先于新性能评估冻结）

本文件在本轮任何新性能计算前写入并以SHA-256锁定。规则为2026-09-07核查后修正，不是原研究预设方案。不依据新AUROC、校准或其他性能选择规则、阈值、医院分区、特征或超参数。相对于保留的v1，唯一改变是将医院生存状态缺失设为互斥流程中的优先不确定类别，以使原始74条缺失状态记录全部明确归入同一类别；该改变不改变纳入集、结局编码或模型输入。

## 1. 范围和索引

原Stage 2b全部8,810条为可追溯基底，原文件保持只读。保持每次住院原第一个符合原无限前填、≥6小时条件的明确零速率停药候选；不移动起点、不改选后续候选。三个医院分区保持原manifest不变。输出独立目录，患者级中间结果仅在内部private目录或内存，不进入交付包。

将停药候选与重启搜索分开。对原识别六类升压药的同药同分钟记录保留最大有效infusiondrugid；从同患者、同次住院的全部有效正速率记录中找起点后首次正速率证据，不要求未来再次明确停药。源单元内时间有效定义为单元开始≤记录分钟≤单元离开。起点本身须属于至少一个有效单元区间。每条原遗漏记录独立核对源正速率、所属患者住院、时间、事件先后和观察条件；不直接批量赋值。

## 2. 时间与生存代理

医院死亡代理：patient医院状态为Expired时的医院出院相对分钟；单元死亡代理：单元状态Expired时的单元离开相对分钟。二者均为行政代理而非精确临床死亡时刻。已知代理在起点之前或等于起点则不具备有效研究起点。

医院Alive/Expired缺失、未知，或任一相关单元的医院状态缺失，均记生存状态不确定。多患者/医院链接、多医院出院时间、冲突医院状态、不同单元死亡代理、医院与单元死亡代理不一致、单元Expired但医院非Expired等均列冲突。无临床依据选择其中一个修补。单元离开晚于医院出院本身不自动排除；但观察时长不能超过医院出院。

## 3. 互斥流程（依次，首先命中即停止）

1. invalid_identity_or_index：编号不一致，索引或医院出院时间缺失。
2. indeterminate_missing_hospital_status：医院生存状态缺失/未知；原始74条全部优先归入本类，不默认存活。
3. invalid_origin_outside_unit：索引不在任何有效单元观察区间。
4. invalid_death_proxy_at_or_before_origin：任一已知死亡代理≤索引，细分早于/等于；不重新标为停药后死亡。
5. indeterminate_death_or_discharge_proxy_conflict：上述代理/状态/出院时间冲突。
6. invalid_alive_discharge_before_origin：医院Alive且出院<索引。
7. 敏感性候选限制（下节）。
8. invalid_or_indeterminate_restart_source：24h内首次正速率存在无效单元时间/编号证据，且该不可信证据早于或等于待判事件；不把忽略异常记录后的空白当作无事件。
9. indeterminate_simultaneous_events：重启与死亡代理同一分钟，不任意打破并列。
10. indeterminate_observation：观察在首个事件或24h之前中断。
11. recorded_restart_first、recorded_death_proxy_first，或no_recorded_restart_or_death_proxy_under_observation。

各标记另保存非互斥汇总，互斥流程报告优先级造成的归属变化；所有类别合计必须等于各分区原始人数。

## 4. 观察条件和事件排序

合并同次住院有效单元区间，重叠或首尾相接允许连续；正长度间隙不填补。观察终点取索引所在连续区间终点与医院出院时间的较早者。首个有效重启/医院死亡代理在(t0,t0+1440]内，并且此前行政观察连续，才可分类；死亡在离开单元后不能自动判为death_first。没有两个已记录事件者须满足观察覆盖至t0+1440，否则不确定。

无事件类别名称仅为“在规定观察条件下未记录重启或死亡代理事件”。行政区间只是记录可观察性条件，不能保证实际输注记录完整、不能证明完整临床无事件。三分类评价是条件于可判定记录的性能，存在选择/谱系偏倚；不能外推到所有停药者。

## 5. 固定敏感性分析（主分析及两项指定敏感性全部报告，不择优）

- primary_traceable：原无限前填候选；修正全量正速率搜索、代理及观察判定。
- freshness_180：原起点不变，候选须在停止前6小时持续具有至少一个180分钟内新鲜的已知正状态；停药前一瞬仍有新鲜正状态，停药时所有此前见过的药物状态须新鲜且为零。有限前填在最后记录超过180分钟后为UNKNOWN，不自动归零。新鲜正状态覆盖可以跨药连续；未知不能延长6小时暴露。未曾记录的药物不凭空补零，仍属数据库可识别范围的局限。
- gap_60：固定起点后须在连续观察下无正速率至少60分钟；≤60分钟有正速率则候选不满足；60分钟内死亡或不足观察则间隔不可判定。它是按起点后信息限制的敏感性人群，不是前瞻性60分钟landmark模型，不声称无选择偏倚。
180分钟为核查前指定的记录时效敏感性阈值，借鉴原特征参数但并非已验证结局标准。有限状态仅用于检查固定候选及其暴露的文档新鲜度；索引后重启仍搜索全部正速率证据，不因未知状态被当成零而制造转换。不把前填的零状态延续当作证明未给药；无事件仍限于上述“未记录事件”与行政观察定义。

由于所有分析起点/前6小时窗口均与原Stage 2b逐条相同，本轮不改变特征计算。若断言发现起点被移动，必须停止，不得使用旧特征；本轮不包含另选候选或重建起点的分析。

## 6. 模型与评价（全部固定）

使用已修正MIMIC primary源模型，另保留已修正strict源模型作为源敏感性；均不重训MIMIC。使用已修正且保存的两个去剂量特征消融源模型（primary及strict）。不使用旧MIMIC原始标签模型。

每个eICU分析分别：源直接外推；仅在recalibration医院拟合截距、截距加斜率；仅在adaptation_development医院克隆原源pipeline及超参数拟合目标库三分类；同样更新两个消融特征集的目标模型。缺少类别/数据导致不可估计则输出NA及原因，不更改限制争取可估计。

锁定评价医院仅用于评价，不调参。主要输出重启的一对其余AUROC、AUPRC、Brier、校准截距/斜率和平均风险。95%置信区间采用1,000次医院聚类百分位bootstrap（种子20260831）；每次医院有放回、携带其全部记录，同次抽样用于所有模型，报告有效次数。该CI条件于已拟合模型，不包含训练/再校准不确定性。配对模型差异使用同次医院抽样。校准统计也报告聚类CI（不可估计重复明确计数）。

修正前后对照以“已修正MIMIC、旧eICU标签”的保存结果为主要旧基线，同时保留原研究结果作为溯源附件；人群与标签变更造成的性能差不声称纯模型改进。输出旧标签到新状态的汇总转移表和738条逐条内部核对的汇总。

## 7. QA及交付

检查冻结规则哈希、源文件前后哈希、分区固定且医院不重叠、起点特征不变、738条证据全部逐条校验、事件排序边界、互斥人数平衡、未知状态不产生零、过期导致6小时断裂、无闭合要求的重启检测、bootstrap单位与配对抽样。原始记录/患者级标签/模型留在内部，不打包；交付规则、可执行代码、依赖路径与哈希、汇总表、局限和QA。
